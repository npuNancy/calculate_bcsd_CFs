## 阶段与优先级

1. 全14账号完整脚本库存、配置、环境、ACL、启动容量验收完成。
2. 唯一 prepare 优先在1352运行，其他有槽worker也可接手；未完成中间冻结和容量复核前不提交extract。
3. extract默认顺序为下述模型→Climate→Station→tech→patch；仅在ready集合中排序，账号有槽即提交，不等待上一模型/情景整组完成。
4. 全部extract成功后由一个worker执行唯一publish，优先1352。全局阶段各一个，不计入3,384提取unit。

| 轴 | 顺序 |
|---|---|
| GCM | CANESM5 → MPI-ESM1-2-HR → MRI-ESM2-0 → BCC-CSM2-MR |
| Climate | ssp126 → ssp245 → ssp585 |
| Station | ssp126 → ssp245 → ssp585 |
| tech | wind → solar |
| patch | land_points_reference降序，同值按patch编号 |

每个GCM有846个unit；每个GCM/Climate有282个；每个GCM/Climate/Station有94个。对角组合共1,128，反事实非对角共2,256，均须运行，不把Station当Climate别名。

## 补槽与重分配

每15分钟在各账号自己的SSH会话查询全部active作业，包含其他项目，每账号最多20、合计最多280。本账号ready不足时，从其他账号尚未提交且依赖满足的任务领取；没有安全ready时如实记录原因，不重复提交。

重分配使用接收账号已有完整包中的相同脚本，保持科学输入/输出、unit_id、logical_owner不变，仅更新submit_username、assignment_version和调度记录。先取得共享提交锁，再取得目标账号锁；重读任务和空槽，写submitting，提交后立即保存JobID。active/submitting/unknown不迁移；失败任务先确认终态再按goal的重试规则处理。

全部规则与身份验收见 [goal.md](../goal.md)。脚本副本数量不等于待运行逻辑任务数量。
