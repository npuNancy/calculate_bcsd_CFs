# CF production_v2 运行前准备

本清单由正式运行的CodingAgent执行并在共享 `runtime/preparation.json` 记录每步状态、时间、证据与缺项。
当前仓库文件建设不代表这些远程步骤已经执行。准备只做部署、轻量权限和配置检查、脚本生成；科学计算由Slurm执行。
BCSD已完成抽检，不新建全量输入检查或全量hash门槛。

先阅读accounts.csv，确认14 worker与1872汇总角色；RUN_ID用新的安全名称，例如 `cf_grid_v2_20260930_v1`。
所有worker使用相同代码SHA、环境和科学参数，不能沿用旧场站脚本。

```text
CF_REPO=$HOME/project_climate/repos/calculate_bcsd_-cfs
```

真实land plan以本批次manifest引用为准；这里是已核查的共享位置。完整BCSD气象结果位于BCSD_ROOT/outputs，CF读取blocks。
环境激活实际执行的是 `source "$CF_CLIMATE_ACTIVATE" climate`，等价于既有共享climate命令。
脚本本身不嵌入任何 `/work/home/<用户名>/...`，只有外部环境配置包含部署路径。

本地修改测试通过后commit、push；14个worker均通过HTTPS部署：


匿名HTTPS不可用时停止部署并报告认证缺项，不复制SSH密钥或将token写URL。

## 2. 1872创建home共享目录及ACL

由1872本人创建新的运行根。先检查路径存在情况，已有运行不能覆盖；备份本次涉及祖先目录的getfacl结果。
下面变量WORKERS由accounts.csv的worker行取得，内容应为14个用户名，不包含1872。

```bash
# 在1872登录环境中执行；CF_RUN_ID、WORKERS由准备控制器传入。
export CF_SHARED_ROOT="$HOME/cf_grid/$CF_RUN_ID"
mkdir -p "$HOME/cf_grid" "$CF_SHARED_ROOT"
for worker in $WORKERS; do
  setfacl -m "u:$worker:--x" "$HOME" "$HOME/cf_grid"
  setfacl -m "u:$worker:rwx,m::rwx" "$CF_SHARED_ROOT"
  setfacl -m "d:u:$worker:rwx,d:m::rwx" "$CF_SHARED_ROOT"
done
# 显式继承汇总账号权限：worker创建的文件，其owner不再是1872。
setfacl -m 'u:acjpoxgsdu:rwx,d:u:acjpoxgsdu:rwx,m::rwx,d:m::rwx' "$CF_SHARED_ROOT"
mkdir -p "$CF_SHARED_ROOT/inputs" "$CF_SHARED_ROOT/outputs" "$CF_SHARED_ROOT/runtime/receipts"
```

已有祖先ACL含更多权限时保留原有权限，仅补缺少的穿越权限，不照抄命令降低已有授权。
父目录只授予穿越，不递归开放1872整个home。共享运行根、outputs和runtime保留14 worker以及1872本人的命名访问ACL及默认ACL，
这样一个worker创建的子目录、年份文件、sidecar和锁文件可由其他worker恢复、1872读取。
计算脚本使用umask0002；仍须通过实际文件读写探测验证ACL有效mask，不只看ACL条目存在。
`inputs/`在配置冻结后改为worker只读：文件`r--`，目录`r-x`，默认ACL也为`r-x`；1872保留写权限。
只修改本轮新目录的ACL，不能递归chmod现有大型结果树。不要在计算进程启动后改变它们的访问权限。

由全部14个worker分别在共享runtime的独立探测子目录中创建小文本，执行原子rename；由另一个worker及1872读取、修改、删除这些探测文件。
清理仅限刚创建的探测文件。由不同账号的两个进程争用同一flock，确认第二个确实被拒绝；测试完保留正式锁文件路径。
运行根的物理路径必须位于1872的home，不以指向share的软链接替代。

检查1872 home的 `df -hT`、`df -i` 及可用的账号quota/平台配额记录。已知df可能显示共享文件系统整体PB容量，
不能把它作为个人可写容量；若无法确认足够容量，报告缺项，不擅自改汇总账号或存储方案。
按46年、300×300、float32，单unit未压缩约48.36GB，1,128unit约54.54TB；实际随压缩和陆海比例变化。
默认没有额外完整final，但重算临时文件及失败副本需预留空间；启用merge时还需容纳年份文件和final同时存在。

## 3. 输入可见性及小配置

不让worker获得气象数据写权限，不在本轮重写上游manifest或删除V1数据。

准备47个patch的core bbox JSON，与patch_assignment.csv及当前BCSD patch定义一致，拷贝到共享inputs。
可以在本地读取已核对的上游纯Python定义生成小JSON，再使用scp非破坏性传输：

```bash
# 当前仓库根目录；此步骤只处理patch定义，不读取气象数组。
python3 - <<'PY'
import csv,json,runpy
from pathlib import Path
upstream=runpy.run_path('../bcsd/global_bcsd/patches.py')
rows=list(csv.DictReader(open('infos/scnet_patchify_grid/作业分工/patch_assignment.csv')))

(p/'patch_manifest.json').write_text(json.dumps({'patches':{q:{'core_bbox_360':upstream['core_bbox_360'](q)} for q in patches}},indent=2)+'\n')
PY
# 确认目标文件不存在或内容相同后，将此文件传到1872的 $CF_SHARED_ROOT/inputs/。
```

冻结 `inputs/release.json`，用标准库读取小JSON和stat即可，不打开全量NC：

```json
{
  "release": "production_v2",
  "run_id": "<RUN_ID>",
  "code_sha": "<完整40位SHA>",
  "models": ["CANESM5", "MPI-ESM1-2-HR", "MRI-ESM2-0", "BCC-CSM2-MR"],
  "years": "2015-2060",
  "bcsd_spot_check_accepted": true,
  "shared_root": "<CF_SHARED_ROOT的真实绝对路径>",
  "bcsd_root": "/work/share/aczlvkl1ac/bcsd_runs/production_v2",
```

## 5. 在每一个worker生成完整作业包

对accounts.csv的14个worker逐个执行同一命令；不能只生成其初始归属patch，不给1872生成：

```bash
export CF_ENV_FILE="$HOME/cf_grid_runs/<RUN_ID>/campaign.env"
source "$CF_ENV_FILE"
mkdir -p "$CF_WORK_ROOT/logs" "$CF_WORK_ROOT/jobs"
cd "$CF_REPO"
python3 infos/scnet_patchify_grid/create_jobs.py \
  --code-sha '<已固定40位SHA>' \
  --jobs-dir "$CF_WORK_ROOT/jobs/cf_grid_v2_v1"
# 逐个验证，不能只检查一个模板。
find "$CF_WORK_ROOT/jobs/cf_grid_v2_v1" -name '*.sh' -exec bash -n {} \;
sha256sum "$CF_WORK_ROOT/jobs/cf_grid_v2_v1/manifest.json"
```

生成器支持dry-run供计数。实际准备验收必须是每账号1,128个唯一.sh、完整manifest、所有脚本通过bash-n，
并重新计算每份脚本SHA与manifest比对；14份manifest SHA完全一致，总15,792份副本。
不能用find命令的总退出码推断每个bash-n都成功，控制器须收集每个检查的退出码，或使用Python逐脚本 `subprocess.run(...,check=True)`。
记录账号、pack目录、profile、code SHA、manifest hash、实际数量、逐脚本校验结果到preparation.json。
文件碰撞时使用新目录；已存在同版完整包可只校验复用，不能为了重新生成删除旧包。

默认profile：10 CPU、8 worker、24小时、tile64×64/time240/压缩2、merge_final=False。
资源profile变更时14账号各生成新版本完整包；普通任务重分配不需要重新生成。

本轮准备命令本身不调用sbatch。

正式提交示例（只由获得运行授权的控制器在goal规定的锁内执行）：

```bash
export CF_ENV_FILE="$HOME/cf_grid_runs/<RUN_ID>/campaign.env"
source "$CF_ENV_FILE"
sbatch --parsable --account="$(id -un)" --chdir="$CF_WORK_ROOT" --export=ALL \
  "$CF_WORK_ROOT/jobs/cf_grid_v2_v1/<台账选择的脚本>.sh"
```

Slurm在shell执行之前打开日志，logs必须预先存在；SBATCH不能展开CF_WORK_ROOT或HOME。
提交后的资源和产物检查遵循goal；不因为准备文档含示例sbatch就提前提交或绕过20槽限制。
